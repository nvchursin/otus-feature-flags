# ADR: тип фронтенда (монолит vs монорепа vs микрофронтенды)

## Status

Accepted.

## Context

Админка `ff-crud` — небольшое spa-приложение: две страницы (список флагов и карточка флага).
Драйвер фронтенда — простота разработки и независимый деплой от `ff-evaluator`.

Нужно выбрать организацию ui: microfrontends, monorepo или простой монолит. Критерии: границы владения, нужна ли независимая поставка частей ui, окупается ли оверхед tooling/runtime.

## Decision

Одно простое spa-приложение (упрощённый fsd), поэтому выбор микрофронтендов или monorepo будет явным оверхедом.

Доводы:

- владеет одна команда — нет независимых владельцев частей админки;
- независимость нужна между админкой и ff-evaluator, а не между страницами; code splitting достаточно для тяжёлых кусков (audit-log);
- mfe и monorepo — это всегда лишний tooling.

## Consequences

Положительные последствия:

- один pipeline и один артефакт на cdn;
- проще dx, e2e и эволюция структуры внутри fsd.

Отрицательные последствия и риски:

- при появлении отдельных команд, независимых релизов частей ui или нескольких продуктов внутри админки решение придётся пересмотреть.
