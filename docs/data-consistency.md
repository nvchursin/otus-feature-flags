# Согласованность данных Feature Flags Service

## Шаг 1. Наборы данных

| Набор                  | Что хранит                                  | Кто пишет        | Кто читает                                |
| ---------------------- | ------------------------------------------- | ---------------- | ----------------------------------------- |
| D1. Конфигурация       | Правила, проценты раскатки, теги, окружения | `ff-crud`        | Админка, `ff-distributor` через `ff-crud` |
| D2. Версии и audit-log | Историю изменений: кто, что и когда поменял | `ff-crud`        | Админка; `ff-distributor` читает версию   |
| D3. Снапшоты в cdn     | Копию конфигурации для раздачи              | `ff-distributor` | `ff-evaluator`                            |
| D4. Кеш evaluator      | Последний загруженный снапшот               | `ff-evaluator`   | `ff-evaluator`                            |
| D5. Кеш приложения     | Полученные значения флагов                  | sdk приложения   | Приложение                                |

## Шаг 2. Цена расхождения и цена отказа

| Набор                  | Что стоит расхождение на 1 с                                                             | Что стоит отказ                                  |
| ---------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------ |
| D1. Конфигурация       | Администратор правит устаревшие правила; без проверки версии может затереть чужую правку | Нельзя менять флаги, приложения работают по кешу |
| D2. Версии и audit-log | История не совпадает с конфигурацией: непонятно, кто изменил флаг                        | Нельзя сохранить изменение                       |
| D3. Снапшоты в cdn     | Часть узлов получает старые правила                                                      | Новые правила не доходят до узлов                |
| D4. Кеш evaluator      | Разные узлы могут выдать разные значения флага                                           | Приложениям берут значения из локального кеша    |
| D5. Кеш приложения     | Пользователь видит прежний вариант                                                       | Приложение использует значения по умолчанию      |

## Шаг 3. Окно свежести

| Набор                  | Окно                             | Как проверить                                                      |
| ---------------------- | -------------------------------- | ------------------------------------------------------------------ |
| D1. Конфигурация       | 0 с после подтверждения записи   | Следующее чтение в админке видит сохранённую версию                |
| D2. Версии и audit-log | 0 сек. относительно конфигурации | Изменение, версия и запись аудита появляются вместе                |
| D3. Снапшоты в CDN     | До 60 сек.                       | Время от сохранения до доступности новой версии через cdn          |
| D4. Кеш evaluator      | До 60 сек.                       | Время от сохранения до применения версии всеми экземплярами        |
| D5. Кеш приложения     | До 60 сек.                       | Время от сохранения до обновления значений в работающем приложении |

## Шаг 4. Модель под каждый набор

| Набор                  | Модель    | Почему                                                                  |
| ---------------------- | --------- | ----------------------------------------------------------------------- |
| D1. Конфигурация       | ACID + CP | Отказ сохранения дешевле потерянной правки; проверяем версию при записи |
| D2. Версии и audit-log | ACID + CP | Изменение без истории не принимаем; пишем всё одной транзакцией         |
| D3. Снапшоты в cdn     | BASE + AP | Старый снапшот лучше недоступного                                       |
| D4. Кеш evaluator      | BASE + AP | Ответ по старым правилам лучше отказа                                   |
| D5. Кеш приложения     | BASE + AP | Приложение должно работать без связи с сервисом                         |
